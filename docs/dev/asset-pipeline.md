# Asset pipeline

Models are built in Blender, exported as glTF binary (`.glb`), and loaded with Three.js.

## Conventions

- **Units:** 1 Blender unit = 1 meter. Apply scale before export (Ctrl+A > Scale).
- **Up axis:** export with **+Y Up** (the glTF exporter default).
- **Origin:** at floor level, centered on the piece's grid footprint.
- **Names:** lowercase-kebab-case, e.g. `hall-straight`, `ossuary-hall`. Object names survive export and are used to find markers.
- **Materials:** Principled BSDF only. Keep textures power-of-two.
- **Location:** `static/assets/<category>/<name>.glb`, e.g. `static/assets/rooms/ossuary-hall.glb`.

## Export settings

File > Export > glTF 2.0:

- Format: **glTF Binary (.glb)**
- Include: Selected Objects (or the piece's collection)
- Transform: +Y Up
- Data: Apply Modifiers on; UVs, Normals on; Tangents off unless using normal maps
- Lighting: do not export lights; lights are placed by the game

## Loading

Register the path in `ASSETS` (`src/lib/game/assets.ts`) and load it:

```ts
const model = await loadModel(ASSETS.devCube);
engine.scene.add(model);
```

Each file downloads once; `loadModel` returns a fresh clone each call.

## Placeholder asset

`static/assets/dev/dev-cube.glb` is generated by `pnpm asset:dev` to verify the pipeline without Blender. Replace it with a real export to confirm your Blender settings.

## Raw art (`art/`, not in git)

```
art/
  blender/catacomb-kit.blend   # map kit source
  textures/<Set>_4K-JPG/       # raw ambientCG / Poly Haven downloads, as downloaded
  export/<piece>.glb           # raw Blender exports (full-res), input to asset:build
```

Everything in `art/` except `art/README.md` is gitignored. Back it up yourself. Only the optimized `.glb` files in `static/assets/` are committed.

From each texture set use `_Color`, `_NormalGL` (glTF uses the OpenGL convention; never `_NormalDX`), `_Roughness`, and `_Metalness` where present. `_Displacement` isn't supported by glTF.

## Map kit

The first catacomb pieces were bootstrapped procedurally by `scripts/blender/kit.py`. In Blender (Text Editor, or through the Blender MCP):

```python
import sys, importlib
sys.path.insert(0, r"D:/Code/undercroft/scripts/blender")
import kit; importlib.reload(kit)
kit.build_all()    # build pieces that do not exist yet; existing ones are skipped
kit.export_all()   # write art/export/<piece>.glb
```

Then run `pnpm asset:build`. Exports with no root empty named after the file (for example a character model) are skipped with a warning; only map pieces go through this build.

**The .blend file is the source of truth.** `kit.py` only bootstrapped the first pieces. Edit pieces by hand in Blender. `build_all()` never touches a collection that already exists. Regenerating one (`kit.build_stairwell(force=True)`) wipes its hand edits, so only do it deliberately. Nothing in the pnpm scripts runs Blender. `export_all()` and `pnpm asset:build` only read your work.

### Conventions

- **Grid:** 4 m cells, 4 m levels. Blender **+Y is north** (it becomes -Z in glTF and Three.js).
- **Root:** an empty named after the piece (`hall-straight`) at the origin. All other objects are parented to it. Custom properties: `footprint_w`, `footprint_d` (cells along X and Y), `levels`, and optionally `max_texture` (default 1024).
- **Origin:** floor of the lowest level, centred on the footprint.
- **Standard `hall` opening:** 2 m wide, vertical sides to 1.8 m, semicircular arch to 2.8 m, centred on a cell edge. Use `kit.hall_profile()`, and the `gauge-opening-hall` in the `_reference` collection to check by eye. Hall passages sweep the same profile, so seams match.
- **Room walls** sit 0.25 m inside the footprint. Each opening gets a short throat out to the boundary.
- **Markers** (empties, kebab-case prefixes):
  - `socket-<type>-<n>`: an opening, at floor level, on the footprint boundary, centred on a cell edge. The edge and cell are derived from the position.
  - `spawn-<n>`: player start. `extract-<n>`: extraction point. `rite-<n>`: where the rite is initiated.
  - `crate-<n>`: where a loot crate may stand (the game fills only some). On the floor at the crate's centre, turned about Z only, with its local +Y pointing at the wall behind the crate. Leave 1.2 m of clear floor in front. `props.crate_marker(piece, x, y, wall)` adds one pushed back against the `'n'`, `'s'`, `'e'` or `'w'` wall near a point, and reports anything in its way.
- **Collision:** `col-*` meshes are unit cubes scaled and rotated into place. They go into the manifest as oriented boxes and are stripped from the shipped model.
- **Volumes:** `vol-<kind>-<n>` unit cubes mark gameplay volumes, such as `vol-water-0` (swimmable water) in the Cistern or `vol-squeeze-0` (slow, no sprinting) in `hall-squeeze`. Like colliders, they go into the manifest and are stripped from the model.
- **Every water volume needs a way out:** steps, or an edge no more than 0.9 m above the water surface (the swim-out mantle height, `MOVEMENT.mantle.maxFromWater`). The Cistern has both: steps on the south side of the basin and a walkway 0.45 m above the water.
- **Water connectors dip below their sockets,** so they declare an extra level with the origin at the bottom and sockets at level 1, like the Cistern:
  - `hall-canal`: a widened passage with a 1 m ledge beside a water channel; the water is 0.3 m below the ledge.
  - `hall-flooded`: a sump. The floor slopes 2 m down and the ceiling dips under the water for about 2 m, so you dive through; the slopes are the shores.
- **Caps** (`cap-hall`) have footprint 0×0. Their single socket is at the origin facing north, and their geometry fills the -Y side (inside the piece they seal).
- **Materials:** single-sided (backface culling on, so they export with `doubleSided: false`). Name them by use (`mat-wall-tunnel`), not by texture, so a texture can be swapped without renaming. Texture sets per material are listed in `MATERIALS` in `kit.py`.
- **UVs:** world-scale, one texture repeat per `tile` metres per material.
- **Budgets:** 1-cell pieces ≤ 5k triangles, rooms ≤ 40k.

Blender adds `.001` suffixes when names repeat across collections (`col-floor.001`). The build script strips them.

## `pnpm asset:build`

`scripts/build-assets.ts` processes every `art/export/*.glb`:

1. **Validates:** the root empty and footprint, that sockets lie on the boundary and are centred on cell edges, that heights sit on a level, and the triangle budget. It exits non-zero naming the piece and marker.
2. **Optimizes:** strips collision meshes, volumes and Blender scene properties, runs dedup, weld, and prune, and re-encodes textures to WebP at 1024 px. The 4K sources are never touched.
3. **Writes shared textures:** each piece becomes `static/assets/map/<piece>.gltf` + `<piece>.bin`. Textures go to `static/assets/map/textures/<content-hash>.webp`, so a texture used by many pieces is stored, committed and downloaded once. On the client, `loadModel` (`src/lib/game/assets.ts`) also points every piece at one GPU texture per file. Output is deterministic: rebuilding unchanged pieces produces identical files, so git only stores what actually changed. The output folder is cleared first, so removed pieces and unused textures don't linger.
4. **Generates `src/lib/shared/map/pieces.generated.ts`:** footprint, sockets, spawns, extracts, rite points, crate markers, colliders, and volumes per piece. The server and client both read it, so the server never parses model files. Commit it with the built assets.

### Creature models

`art/export/creatures/*.glb` (skinned, with animations) skip the piece checks. Each one keeps its skin and animation clips, is deduplicated and pruned, has its textures re-encoded to WebP at 1024 px, and is written to `static/assets/creatures/<name>.glb`. The witch drops from 53 MB to about 2.4 MB.

The explorer (every player's body) goes through the same pass: `art/export/player/*.glb` to `static/assets/player/<name>.glb` (18.7 MB to about 3.9 MB). See [player.md](player.md#player-model).

On the client, `loadCharacter` clones with SkeletonUtils (a plain `clone` breaks skinned meshes) and strips horizontal root motion from the root bone. See [creatures.md](creatures.md).

### Item models

Weapons, ammo and consumables are built by `scripts/blender/items.py` in the kit .blend, each in its own `item-<id>` collection under a root empty. As with pieces, building skips existing collections, so hand edits are kept.

- **Origin:** at the grip.
- **Orientation:** forward is +Y (the barrel or blade), up is +Z.
- **Materials:** plain PBR colours, no textures.

`items.export_all()` writes `art/export/items/<id>.glb`. `pnpm asset:build` dedups, welds and prunes each one into `static/assets/items/<id>.glb` (a few KB each). See [items.md](items.md).

#### Item models from elsewhere

A model that wasn't built by `items.py` (sculpted or generated: centred on the origin, facing any way, any size, heavy and textured) can be dropped into `art/export/items/<id>.glb` as it is. Give it an entry in `scripts/items.config.ts` and the build stands it up in the item frame:

- `forward`: the direction in the raw file that the muzzle, blade tip or hook points (`'-x'`, `'+y'`...);
- `up`: the direction in the raw file that is its top;
- `length`: its length in the game, in metres. The model is scaled to it;
- `grip`: where the hand goes, as `[from the back end, from the bottom]`, each 0..1. That point becomes the origin.

If it comes out back to front or upside down in the hand, flip the sign of `forward` or `up` and rebuild. A model with no entry is left as exported, and the build says so.

Whatever its source, an item over 6,000 triangles is simplified down to that, and its textures are re-encoded to WebP at 512 px. The generated shotgun goes from 184,000 triangles and 13.6 MB to 6,000 and about 400 KB.

### Props

Things that stand in the map but aren't part of a piece: for now the loot crate. `scripts/blender/props.py` builds them in the kit .blend, each in a `prop-<name>` collection under a root empty; as with pieces and items, building skips a collection that exists.

- **Origin:** on the floor, centred. The front faces -Y; the back (+Y) goes against a wall.
- **Moving parts** are their own objects with the origin on the pivot. The crate's lid, `crate-lid`, has its origin on the back top edge; the game turns it about its X axis.
- **Materials:** textured, from the sets in `kit.MATERIALS` (`mat-prop-planks` uses `Planks025A`).

`props.export_all()` writes `art/export/props/<name>.glb`. `pnpm asset:build` re-encodes the textures to WebP at 512 px and writes `static/assets/props/<name>.glb`, keeping node names (the game looks the lid up by name).

## Audio

Raw recordings go in `art/sfx/` (gitignored), named as downloaded. `pnpm asset:audio` (`scripts/build-audio.ts`) builds the entries listed in `scripts/audio.config.ts`:

1. Reads 16-bit PCM WAV or MP3 (any channel count or sample rate; MP3 is decoded with `mpg123-decoder`, mpg123 compiled to WebAssembly) and mixes to mono.
2. Low-pass filters and resamples to 32 kHz, or to the entry's `rate` (22050 for long, dark ambience: about half the size).
3. Optionally `crop`s to a section. Then it trims silence relative to the peak, or slices a recording of several hits into one file per hit (`maxClips` keeps at most that many, spread through the recording). `loopCrossfade` crossfades a clip's end into its start, for seamless loops such as water lapping. An entry can also list several source files, each becoming a variant of the same sound. Slicing uses onset detection (`slice: { minGap, maxLength, threshold }`), for example one footstep per file from a walking recording. Loops can set `keepSilence`.
4. Normalizes to -1 dBFS, adds short fades, and writes mono WAV to `static/assets/audio/<id>.wav` (or `<id>-<n>.wav` for slices).
5. Writes `src/lib/content/audio/files.generated.ts`, mapping each id to its variant URLs.

The build writes uncompressed mono WAV: no native encoder or downloaded binary is needed. The current set is about 3.2 MB. If the library grows (music, long ambience), switch the output to a compressed format. A pure-JavaScript MP3 encoder would avoid native binaries, but MP3 adds a short silence at the start of each file, so seamless loops would need to stay WAV.

**Adding a sound:**

1. Drop the WAV in `art/sfx/` and add an entry to `scripts/audio.config.ts`.
2. Run `pnpm asset:audio`.
3. Point a sound in `src/lib/content/audio/sounds.ts` at it with `file: '<id>'`.

Only sounds listed in the config are built and committed. Recordings for later features stay in `art/sfx/` until they're used.

## Interface art

Pictures for screens outside the catacombs go in `art/images/` (gitignored) as PNG, JPEG or WebP. `pnpm asset:images` (`scripts/build-images.ts`) converts every one to WebP in `static/assets/images/`, keeping the file name, scaled down to at most 2560 px wide.

It then writes `src/lib/content/images.generated.ts`, a content hash for every picture in that folder. Always refer to a picture through `imageUrl(name)` (`src/lib/content/images.ts`), never a bare `/assets/images/...` path: the URL carries the hash (`?v=...`), so a rebuilt picture gets a new URL and browsers can't keep showing an old cached copy. Commit the generated file with the pictures.

`login-bg` is the picture behind sign-in, the dashboard and the party screen. It is applied by the global `.backdrop-art` class in `src/app.css`, which darkens it so text stays readable; the element also sets `style:--backdrop-image={BACKDROP_IMAGE}` (the hashed URL). Adding `use:parallax` (`src/lib/ui/parallax.ts`) to the same element makes the picture drift away from the cursor; it is skipped for people who ask for reduced motion. To change the picture, replace `art/images/login-bg.png` and run `pnpm asset:images`. To put it behind another screen, add the class, `style:--backdrop-image={BACKDROP_IMAGE}` and `use:parallax` to that screen's outer element. The expedition results screen uses it too.

Each pane on the Afflictions page has a picture, named by `AfflictionDef.image` in `src/lib/content/afflictions.ts`: `affliction-gloaming-banner` for the Gloaming, and `affliction-unknown-banner` for the panes of Afflictions nobody has met. A pane is 400px wide; the picture is fitted to that width and aligned to the top, the name sits over its first 250px, and below that it fades out behind the text. So make it portrait, at least 800px wide (for sharp screens), with the subject in the top part. Until a picture exists the pane shows a plain dark fade.
