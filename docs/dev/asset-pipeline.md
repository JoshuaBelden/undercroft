# Asset pipeline

Models are built in Blender, exported as glTF binary (`.glb`), and loaded with Three.js.

To see what is built, what is still a placeholder or synthesized and what is missing, open the admin app's [Art & Assets page](admin.md#art-and-assets).

## Conventions

- **Units:** 1 Blender unit = 1 meter. Apply scale before export (Ctrl+A > Scale).
- **Up axis:** export with **+Y Up** (the glTF exporter default).
- **Origin:** at floor level, centered on the piece's grid footprint.
- **Names:** lowercase-kebab-case, e.g. `hall-straight`, `ossuary-hall`. Object names survive export and are used to find markers.
- **Materials:** Principled BSDF only. Keep textures power-of-two.
- **Location:** built files live in `static/assets/` under content-hashed names (see [Delivery](#delivery)).

## Export settings

File > Export > glTF 2.0:

- Format: **glTF Binary (.glb)**
- Include: Selected Objects (or the piece's collection)
- Transform: +Y Up
- Data: Apply Modifiers on; UVs, Normals on; Tangents off unless using normal maps
- Lighting: do not export lights; lights are placed by the game

## Loading

Look the built file up by its path without the hash and load it:

```ts
const model = await loadModel(modelUrl('shared/props/crate.glb'));
engine.scene.add(model);
```

`modelUrl` (`src/lib/content/models.ts`) reads `src/lib/content/models.generated.ts`, which `pnpm asset:build` writes; a path that was never built fails `pnpm check`. Never write a bare `/assets/...` URL. Each file downloads once; `loadModel` returns a fresh clone each call. The loader decodes meshopt-compressed meshes (`MeshoptDecoder`).

## Delivery

Every run should download only what it uses, load it all before the player takes control, and never download a file twice.

**Folders.** `static/assets/` is split by owner:

```
shared/            map, textures, creatures, player, items, props, audio: every run
ui/images/         interface pictures (hub, menus)
afflictions/<id>/  map, creatures: only runs against that Affliction
dev/               the placeholder cube (dev only)
```

A map piece belongs to an Affliction when its kit entry says so (`affliction` in `src/lib/content/map/kit.ts`; the generator also only places it in that Affliction's maps, see [map-generation.md](map-generation.md)). A creature belongs to one when its raw export sits in `art/export/afflictions/<id>/creatures/` (the Gloaming's boss). The build scripts clear their output folders first, so a moved or removed file doesn't linger.

**Content-hashed names.** Every built file is named `<name>.<hash>.<ext>` (`scripts/hashed.ts`): its name changes whenever its contents do, so the production proxy serves `/assets/*` as `immutable` with a one-year max-age (see [deployment.md](deployment.md)). Code finds files through the generated manifests: `PIECES` (map pieces), `modelUrl()` (other models), `AUDIO_FILES` (sounds) and `imageUrl()` (pictures). Map textures are named by their hash alone and shared by every piece. Builds must be deterministic, so a file that didn't change keeps its name and stays cached: the Opus encoder runs with `-fflags +bitexact` (WebM otherwise writes a random segment id and the date into every file). Check after changing a build script: run it twice, and `git status` should show nothing new.

**Compression.** Meshes use `EXT_meshopt_compression` (map pieces with 16-bit positions so seams between pieces stay closed). Props are left uncompressed: quantization rewrites mesh node transforms, and the game animates the crate lid's node. Textures are WebP; sounds are Opus.

**Preloading** (`src/lib/game/preload.ts`):

- `prefetchCore` starts when the hub opens (`startPrefetch` in `src/lib/game/prefetch.svelte.ts`). It loads every shared model into the loader caches and fetches every sound into the browser cache, at low priority. The Expedition page shows "Preparing the descent... n%" until it's done.
- `preloadRun` runs when a map arrives (`welcome`, or an admin regenerate). Behind the "Descending" bar (`DescentLoading.svelte`) it loads the map's pieces, the explorer, creatures, items and props, the Affliction's own models, and decodes every sound. Take Control appears and the descent stinger plays only once it's done, so nothing pops in or plays late mid-run. Progress is counted in bytes, from the sizes the build manifests record.

A new model or sound is picked up automatically if it's in the content data (`CREATURES`, `ITEMS`, an Affliction's `manifestation.body`, `AUDIO_FILES`). A model loaded some other way needs adding to `sharedModels()` in `preload.ts`.

## Raw art

The raw art is its own **private** repository, [undercroft-art](https://github.com/JoshuaBelden/undercroft-art), with its binary files in [Git LFS](https://git-lfs.com). It is cloned into `art/`, which this repository ignores.

**You only need it to change art.** The built, optimized assets in `static/assets/` are committed here, so working on code needs no LFS and no `art/`. It is private because the raw sources are all rights reserved (`LICENSE-ASSETS.md`), some downloads (Pixabay sounds) can't be redistributed as they are, and LFS storage and downloads count against the owner's GitHub quota (10 GiB of each a month on the free plan).

### What Git LFS does

Git LFS keeps large files out of the git history. The repository stores a small text _pointer_ for each one (`version https://git-lfs...`, an id and a size), and the file itself lives on GitHub's LFS storage. `git clone`, `pull` and `checkout` download the real files in place of the pointers, and `git push` uploads new ones. Which files go to LFS is set by `art/.gitattributes` (by extension: `.blend`, `.glb`, `.jpg`, `.png`, `.webp`, `.wav`, `.mp3` and a few more). Small text files stay in plain git. Once it is installed you use git as usual; the rest of this section is what's different.

### Getting set up

1. **Install Git LFS**, once per machine. It comes with Git for Windows; on macOS `brew install git-lfs`, on Debian or Ubuntu `sudo apt install git-lfs`. Then turn it on for your user:

   ```
   git lfs install
   ```

2. **Get access**: ask the owner to add you to undercroft-art on GitHub.
3. **Clone it into `art/`** inside your undercroft checkout (about 2 GB):

   ```
   cd undercroft
   git clone https://github.com/JoshuaBelden/undercroft-art.git art
   ```

4. **Write the map-piece exports** (needs Blender, see below), then build:

   ```
   pnpm asset:export
   pnpm asset:build
   ```

Check it worked: `git -C art lfs ls-files` lists every LFS file with `*` when it is downloaded and `-` when only its pointer is there. If you cloned before installing Git LFS, they are all `-`; run `git lfs install`, then `git -C art lfs pull`.

### Day to day

- The two repositories are separate: pull both (`git pull`, then `git -C art pull`), and commit and push art changes inside `art/`.
- After pulling a change to `catacomb-kit.blend`, run `pnpm asset:export` and `pnpm asset:build`.
- When an art change goes with a code change (a new piece and its `MAP_KIT` entry, say), push the art first, then commit the code and the rebuilt `static/assets/` here, and name the art commit in the message.
- **Only one person edits a `.blend` at a time.** Binary files can't be merged: if two people change `catacomb-kit.blend`, one of them has to throw their changes away. Say so before you start, or lock it: `git -C art lfs lock blender/catacomb-kit.blend` (and `git lfs unlock` when you've pushed). `git lfs locks` shows who has what.

### Committing art

- Put files where `art/README.md` says. Most binary types are already tracked; to add a new one (say `.tga`), track it **before** you add the files: `git -C art lfs track "*.tga"`, and commit the changed `.gitattributes` with them.
- Before pushing, check the new files are in LFS: `git -C art lfs ls-files` should list them. A large file committed by mistake as a plain git file can be moved while it is still unpushed: `git -C art lfs migrate import --include="*.tga"`. Once it is pushed, it stays in the history for good.
- Commit an export or a `.blend` when it is done, not after every save: every commit of a changed file stores the whole file again.
- Don't commit the map-piece exports (`art/export/<piece>.glb`) or Blender's backups (`.blend1`); `art/.gitignore` leaves them out.

### Saving the quota

A full clone downloads about 2 GB. If you only need part of it, for example the sounds, clone without the LFS files and fetch just those:

```
GIT_LFS_SKIP_SMUDGE=1 git clone https://github.com/JoshuaBelden/undercroft-art.git art
git -C art config lfs.fetchinclude "sfx/**"
git -C art lfs pull
```

(In PowerShell, set the variable first: `$env:GIT_LFS_SKIP_SMUDGE=1`.) From then on pulls only download what `lfs.fetchinclude` matches; `git -C art config --unset lfs.fetchinclude` and `git -C art lfs pull` get the rest. Note that `pnpm asset:export` needs the `.blend` and all of `textures/`.

### When something's wrong

- **`pnpm asset:export` says files are still Git LFS pointers**: they haven't been downloaded. Run `git -C art lfs pull` (and check `lfs.fetchinclude` if you set it).
- **A model or texture won't open, or is a few hundred bytes**: same thing, a pointer (`-` in `git -C art lfs ls-files`); `git -C art lfs pull`.
- **Push rejected, or "LFS: ... over quota"**: the owner's monthly LFS allowance is used up. Wait for it to reset or ask the owner; nothing is lost locally.
- **`git -C art status` shows files changed that you didn't touch**: usually Git LFS isn't installed for your user. Run `git lfs install`. If they still show, and you are sure you have no changes of your own there, `git -C art checkout -- <path>` puts them back as committed (it throws away changes to those files).

```
art/
  blender/catacomb-kit.blend   # map kit source
  textures/<Set>_4K-JPG/       # raw ambientCG / Poly Haven downloads, as downloaded
  sfx/, images/                # raw recordings and interface art
  export/items/, props/, ...   # exports with no other source, in the repository
  export/<piece>.glb           # map pieces: not stored, written by `pnpm asset:export`
```

**Map-piece exports aren't stored.** They are most of the size (about 3 GB), and they come out of the .blend byte for byte the same every time. `pnpm asset:export` (`scripts/export-map.ts`) finds Blender (`BLENDER`, the usual install folder, or the PATH), opens `catacomb-kit.blend` headless and runs `scripts/blender/export_map.py`, which exports every piece in `kit.PIECES` that the .blend has, without saving it. It refuses to run while the .blend or a texture is still an LFS pointer (not yet downloaded), since Blender would otherwise export the pieces with no textures. Run it after changing the .blend or pulling a change to it, then `pnpm asset:build`.

From each texture set use `_Color`, `_NormalGL` (glTF uses the OpenGL convention; never `_NormalDX`), `_Roughness`, and `_Metalness` where present. `_Displacement` isn't supported by glTF.

## Map kit

The first catacomb pieces were bootstrapped procedurally by `scripts/blender/kit.py`. In Blender (Text Editor, or through the Blender MCP):

```python
import sys, importlib
sys.path.insert(0, r"D:/Code/undercroft/scripts/blender")
import kit; importlib.reload(kit)
kit.build_all()    # build pieces that do not exist yet; existing ones are skipped
kit.export_all()   # write art/export/<piece>.glb (or `pnpm asset:export`, without opening Blender)
```

Then run `pnpm asset:build`. Exports with no root empty named after the file (for example a character model) are skipped with a warning; only map pieces go through this build.

**The .blend file is the source of truth.** `kit.py` only bootstrapped the first pieces. Edit pieces by hand in Blender. `build_all()` never touches a collection that already exists. Regenerating one (`kit.build_angel_well(force=True)`) wipes its hand edits, so only do it deliberately. The only pnpm script that runs Blender is `pnpm asset:export`, and it never saves the .blend. `export_all()` and `pnpm asset:build` only read your work. Commit .blend changes to undercroft-art when they are done rather than after every save: each commit stores the whole file again in LFS.

## Conventions

- **Grid:** 4 m cells, 4 m levels. Blender **+Y is north** (it becomes -Z in glTF and Three.js).
- **Root:** an empty named after the piece (`hall-straight`) at the origin. All other objects are parented to it. Custom properties: `footprint_w`, `footprint_d` (cells along X and Y), `levels`, and optionally `max_texture` (default 1024) and `headroom` (m the piece may rise over its top level, only for a piece nothing is ever built over: the start room's dome).
- **Origin:** floor of the lowest level, centred on the footprint.
- **Standard `hall` opening:** 2 m wide, vertical sides to 1.8 m, semicircular arch to 2.8 m, centred on a cell edge. Use `kit.hall_profile()`, and the `gauge-opening-hall` in the `_reference` collection to check by eye. Hall passages sweep the same profile, so seams match.
- **`gate` opening:** the double door between levels: 3.2 m wide, sides to 2.2 m, arch to 3.2 m (`kit.gate_profile()`, `GATE_HALF_W`, `GATE_SPRING`). It has the same point count as the hall profile, so a passage can `morph` from one to the other. Behind the door, `stairs-deep` narrows from gate to hall before the stairs begin.
- **Room walls** sit 0.25 m inside the footprint. Each opening gets a short throat out to the boundary.
- **Markers** (empties, kebab-case prefixes):
  - `socket-<type>-<n>`: an opening, at floor level, on the footprint boundary, centred on a cell edge. The edge and cell are derived from the position.
  - `spawn-<n>`: player start, one per party member: players take them in the order they join, facing the middle of the room (the start room, `angel-well`, has four, `WELL_SPAWNS`). `extract-<n>`: extraction point, at the foot of a ladder made with `extraction_ladder` (see `build_extraction_shaft`, and `add_chapel_extraction`, which added one to the hand-edited chapel without rebuilding it). `rite-<n>`: where the rite is initiated.
  - `rope-<n>`: the top of a rope players climb, hanging straight down. Custom properties: `length` (m it hangs) and, on a way out, `exit` (how far up it you get out). Use `kit.rope_anchor`; `extraction-gate` has one up its shaft (`ropes_for_extractions` put it in the hand-edited .blend, and `build_extraction_gate` builds it). See [rope.md](rope.md).
  - `anchor-<n>`: where a rope can be tied at the top of a drop. On the ledge floor at the edge, turned about Z only, with its local +Y out over the drop. `kit.rope_post` adds one with its post beside it. With a custom property `rope` (m), a rope is tied there for good instead: one of the map's ropes, climbed from the ledge, that nobody unties. It is measured from where a climber's hands reach at the top (0.9 m over the ledge) to where their feet are at its end, and when that is above the floor, it hangs free (the start room's, see [rope.md](rope.md#the-start-rope)).
  - `door-<n>`: a door, on the floor in the middle of the doorway, its local +Y pointing to the room side (the leaves swing away from it). The game stands `prop-door-double` there and makes it solid until opened (see [map-generation.md](map-generation.md#doors)). Only `stairs-deep` has one.
  - `rubble-<n>`: a collapsed wall, on the floor at the foot of the fall. Bricks lie only by these, 1 to 3 at each (see [items.md](items.md)).
  - `candle-<n>`: a candle's wick, just over the top of the wax (which is part of the mesh; `kit._candle` adds both). The game draws a flame at each and lights the room with one light (see [map-generation.md](map-generation.md#candles)).
  - `creature-<n>`: where a creature may start, on the floor with standing room (it snaps to the nav grid within 2 m). Markers too close to the start are skipped; with too few, creatures start in dead-end corners instead (see [creatures.md](creatures.md#spawning)).
  - `crate-<n>`: where a loot crate may stand (the game fills only some). On the floor at the crate's centre, turned about Z only, with its local +Y pointing at the wall behind the crate. Leave 1.2 m of clear floor in front. `props.crate_marker(piece, x, y, wall)` adds one pushed back against the `'n'`, `'s'`, `'e'` or `'w'` wall near a point, and reports anything in its way.
- **Collision:** `col-*` meshes are unit cubes scaled and rotated into place. They go into the manifest as oriented boxes and are stripped from the shipped model. Keep the boxes inside the visible rock everywhere the player can reach, because walls are single-sided: a player whose camera ends up inside the rock sees the void and the pieces behind it. Where a passage narrows or lowers gradually (the ease into `hall-crawl` and `hall-squeeze`), step the boxes every 0.2 m to follow it (`narrow_end_cols` in `kit.py`). The walls should count only below the head of the tallest stance that fits, and the ceiling box should cover the arch across the capsule's reach. Every rock face also has to be closed: an open edge anywhere except a socket ring shows up as a see-through gap.
- **Volumes:** `vol-<kind>-<n>` unit cubes mark gameplay volumes, such as `vol-water-0` (swimmable water) in the Cistern or `vol-squeeze-0` (slow, no sprinting, no fighting) in `hall-squeeze-long`. Like colliders, they go into the manifest and are stripped from the model.
- **Every water volume needs a way out:** steps, or an edge no more than 0.9 m above the water surface (the swim-out mantle height, `MOVEMENT.mantle.maxFromWater`). The Cistern has both: steps on the south side of the basin and a walkway 0.45 m above the water.
- **Water connectors dip below their sockets,** so they declare an extra level with the origin at the bottom and sockets at level 1, like the Cistern:
  - `hall-canal`: a widened passage with a 1 m ledge beside a water channel; the water is 0.3 m below the ledge.
  - `hall-flooded`: a sump. The floor slopes 2 m down and the ceiling dips under the water for about 2 m, so you dive through; the slopes are the shores.
- **Caps** (`cap-hall`) have footprint 0×0. Their single socket is at the origin facing north, and their geometry fills the -Y side (inside the piece they seal).
- **Materials:** single-sided (backface culling on, so they export with `doubleSided: false`). Name them by use (`mat-wall-tunnel`), not by texture, so a texture can be swapped without renaming. Texture sets per material are listed in `MATERIALS` in `kit.py`.
- **UVs:** world-scale, one texture repeat per `tile` metres per material.
- **Budgets:** 1-cell pieces ≤ 5k triangles, rooms ≤ 40k.

**Level pieces** (`build_extraction_gate` and `build_stairs_deep` in kit.py):

- `extraction-gate` is a 3×2 room with the shaft in the middle and a rope up it (`rope-0`, the way out), three hall openings, and the `gate` in its north wall framed in marble.
- `stairs-deep` is 1×6 cells and 4 levels: the `gate` at the top (level 3) with the door just inside it, the narrowing, then two 30-riser flights with a landing between, down to a hall at level 0.

**Big rooms:** `room-vault` (3×3, four pillars round a bier, an opening on every side) and `room-gallery` (4×2, niches three high down both long walls, two openings at each end). `hall-squeeze-long` is the squeeze stretched to 3 cells, about 9 m of it tight.

**The door** is a prop (`props.build_door_double`): two `mat-prop-door` (PaintedWood007B) leaves, `door-leaf-l` and `door-leaf-r`, with their origins on their hinges, and a `door-bar` across them on the room side.

Blender adds `.001` suffixes when names repeat across collections (`col-floor.001`). The build script strips them.

## `pnpm asset:build`

`scripts/build-assets.ts` processes every `art/export/*.glb`:

1. **Validates:** the root empty and footprint, that sockets lie on the boundary and are centred on cell edges, that heights sit on a level, and the triangle budget. It exits non-zero naming the piece and marker.
2. **Optimizes:** strips collision meshes, volumes and Blender scene properties, runs dedup, weld, and prune, re-encodes textures to WebP at 1024 px, and compresses the meshes (meshopt). The 4K sources are never touched.
3. **Writes shared textures:** each piece becomes `static/assets/shared/map/<piece>.<hash>.gltf` + `<piece>.<hash>.bin` (or `afflictions/<id>/map/` for a piece owned by an Affliction). Textures go to `static/assets/shared/textures/<content-hash>.webp`, so a texture used by many pieces is stored, committed and downloaded once. On the client, `loadModel` (`src/lib/game/assets.ts`) also points every piece at one GPU texture per file. Output is deterministic: rebuilding unchanged pieces produces identical files, so git only stores what actually changed. The output folder is cleared first, so removed pieces and unused textures don't linger.
4. **Generates `src/lib/shared/map/pieces.generated.ts`:** URL and download size, footprint, sockets, spawns, extracts, rite points, crate markers, colliders, and volumes per piece. The server and client both read it, so the server never parses model files. Commit it with the built assets.

### Creature models

`art/export/creatures/*.glb` (skinned, with animations) skip the piece checks. Each one keeps its skin and animation clips, is deduplicated and pruned, has its textures re-encoded to WebP at 1024 px, and is meshopt-compressed and written to `static/assets/shared/creatures/<name>.<hash>.glb`. The witch drops from 53 MB to about 1.3 MB. Creatures in `art/export/afflictions/<id>/creatures/` go to `static/assets/afflictions/<id>/creatures/` (the Gloaming's boss, about 1 MB).

The explorer (every player's body) goes through the same pass: `art/export/player/*.glb` to `static/assets/shared/player/<name>.<hash>.glb` (18.9 MB to about 1.9 MB). See [player.md](player.md#player-model).

### The explorer

The explorer's source is `art/blender/Explorer.blend`: the rig, the mesh and every clip as an NLA track. `art/export/player/explorer.glb` is its Mixamo export, and isn't written again from Blender. The glTF exporter resamples every clip to whole frames, which changes each one's length (a loop then hitches), and it re-encodes the mesh.

The clips made since, for holding and using items (see [player.md](player.md#holding-and-using-items)), are built by `scripts/blender/explorer.py` and exported on their own, on the bare skeleton, to `art/export/player/explorer-clips.glb`:

```python
import sys, importlib
sys.path.insert(0, r"D:/Code/undercroft/scripts/blender")
import explorer; importlib.reload(explorer)
explorer.build_all()   # every clip in CLIPS, as actions and NLA tracks in the .blend
explorer.export()      # art/export/player/explorer-clips.glb
```

`pnpm asset:build` merges any `<name>-clips.glb` beside a rigged `<name>.glb` into it by bone name (`mergeClips`, `scripts/clips.ts`). It keeps a clip's rotation channels that move a bone off its rest pose, so a bone the clip leaves alone follows whatever else is playing. Both files must share the skeleton: a bone resting differently stops the build, and so does a clip already in the model.

The same script places items in the hand for their `grip` (`GRIPS`, `show_item`, `grip_numbers`; see [items.md](items.md#data)).

On the client, `loadCharacter` clones with SkeletonUtils (a plain `clone` breaks skinned meshes) and strips horizontal root motion from the root bone. See [creatures.md](creatures.md).

### Item models

Weapons, ammo and consumables are built by `scripts/blender/items.py` in the kit .blend, each in its own `item-<id>` collection under a root empty. As with pieces, building skips existing collections, so hand edits are kept.

- **Origin:** at the grip.
- **Orientation:** forward is +Y (the barrel or blade), up is +Z.
- **Materials:** plain PBR colours, no textures.

`items.export_all()` writes `art/export/items/<id>.glb`. `pnpm asset:build` dedups, welds and prunes and meshopt-compresses each one into `static/assets/shared/items/<id>.<hash>.glb` (a few KB each). See [items.md](items.md).

#### Item models from elsewhere

A model that wasn't built by `items.py` (sculpted or generated: centred on the origin, facing any way, any size, heavy and textured) can be dropped into `art/export/items/<id>.glb` as it is. Give it an entry in `scripts/items.config.ts` and the build stands it up in the item frame:

- `forward`: the direction in the raw file that the muzzle, blade tip or hook points (`'-x'`, `'+y'`...);
- `up`: the direction in the raw file that is its top;
- `length`: its length in the game, in metres. The model is scaled to it;
- `grip`: where the hand goes, as `[from the back end, from the bottom]`, each 0..1. That point becomes the origin.

If it comes out back to front or upside down in the hand, flip the sign of `forward` or `up` and rebuild. A model with no entry is left as exported, and the build says so.

Whatever its source, an item over 6,000 triangles is simplified down to that, and its textures are re-encoded to WebP at 512 px. The generated shotgun goes from 184,000 triangles and 13.6 MB to 6,000 and about 400 KB.

### Props

Things that stand in the map but aren't part of a piece: the loot crate and the corpse. `scripts/blender/props.py` builds them in the kit .blend, each in a `prop-<name>` collection under a root empty; as with pieces and items, building skips a collection that exists.

- **Origin:** on the floor, centred. The front faces -Y; the back (+Y) goes against a wall.
- **Moving parts** are their own objects with the origin on the pivot. The crate's lid, `crate-lid`, has its origin on the back top edge; the game turns it about its X axis.
- **Materials:** textured, from the sets in `kit.MATERIALS` (`mat-prop-planks` uses `Planks025A`).

`props.export_all()` writes `art/export/props/<name>.glb`. `pnpm asset:build` re-encodes the textures to WebP at 512 px and writes `static/assets/shared/props/<name>.<hash>.glb`, keeping node names (the game looks the lid up by name).

**Props from elsewhere** (scanned or generated, like `corpse.glb`: heavy, sitting anywhere) go in `art/export/props/` as they are, with an entry in `PROP_FIT` in `scripts/build-assets.ts`. The build scales them by the entry's `scale` (to life size: the corpse scan came in about 1.7x too big, so 0.6), stands them on the floor (lowest point at y = 0), centres them on the origin and simplifies them to the entry's `tris` (the corpse: 2 million to 12,000 triangles, 64.7 MB to about 600 KB). A static model belongs here, not in `art/export/creatures/` (that pass is for rigged, animated models and simplifies nothing).

### Decor

Models from elsewhere that are built into a piece rather than standing in the map on their own, like the angel statue in the start room, go in `art/export/decor/` (tracked in undercroft-art, and never read by `pnpm asset:build`). The piece's builder imports, simplifies and places them: `kit.import_angel` brings in `decor/angel.glb`, welds the vertices the glTF importer split along UV seams (or simplifying tears it apart along them), simplifies it to `ANGEL_TRIS` (14,000) triangles, scales it to `ANGEL_HEIGHT` and stands it on its plinth, keeping its own material (`mat-angel`) and textures. They ship as part of the piece, so its triangle budget covers them.

## Audio

Raw recordings go in `art/sfx/` (in undercroft-art, see [Raw art](#raw-art)), named as downloaded. `pnpm asset:audio` (`scripts/build-audio.ts`) builds the entries listed in `scripts/audio.config.ts`:

1. Reads 16-bit PCM WAV or MP3 (any channel count or sample rate; MP3 is decoded with `mpg123-decoder`, mpg123 compiled to WebAssembly) and mixes to mono.
2. Low-pass filters and resamples to 32 kHz, or to the entry's `rate` (22050 for long, dark ambience: about half the size).
3. Optionally `crop`s to a section. Then it trims silence relative to the peak, or slices a recording of several hits into one file per hit (`maxClips` keeps at most that many, spread through the recording). `loopCrossfade` crossfades a clip's end into its start, for seamless loops such as water lapping. That blends the end into the opening, so for music add `loopFrom` (seconds): the clip keeps its opening and plays from its start once, its end crossfades into `loopFrom`, and later passes loop from there. The point each loop returns to is written to `AUDIO_LOOP_STARTS` in the generated file list. An entry can also list several source files, each becoming a variant of the same sound. Slicing uses onset detection (`slice: { minGap, maxLength, threshold }`), for example one footstep per file from a walking recording. Loops can set `keepSilence`.
4. Normalizes to -1 dBFS, adds short fades, and encodes mono Opus in WebM (48 kbps, 64 kbps for loops) to `static/assets/shared/audio/<id>.<hash>.webm` (or `<id>-<n>.<hash>.webm` for slices). The encoder is the ffmpeg binary from the `ffmpeg-static` dev dependency, so nothing needs installing.
5. Writes `src/lib/content/audio/files.generated.ts`, mapping each id to its variant URLs (`AUDIO_FILES`) and each file to its size (`AUDIO_BYTES`).

The whole set is about 0.9 MB (it was 7.1 MB as WAV). Opus in WebM decodes through `decodeAudioData` in current Chrome, Firefox and Edge. WebM records the encoder delay, so loops should stay seamless; check Safari and the loops by ear after changing the encoder settings.

**Adding a sound:**

1. Drop the WAV in `art/sfx/` and add an entry to `scripts/audio.config.ts`.
2. Run `pnpm asset:audio`.
3. Point a sound in `src/lib/content/audio/sounds.ts` at it with `file: '<id>'`.

Only sounds listed in the config are built and committed. Recordings for later features stay in `art/sfx/` until they're used.

Then run `pnpm asset:levels` so the admin app has its level (see [Mix](player.md#mix)).

## Interface art

Pictures for screens outside the catacombs go in `art/images/` (in undercroft-art) as PNG, JPEG or WebP. `pnpm asset:images` (`scripts/build-images.ts`) converts every one to WebP in `static/assets/ui/images/` as `<name>.<hash>.webp`, scaled down to at most 2560 px wide.

It then writes `src/lib/content/images.generated.ts`, the URL of every picture. Always refer to a picture through `imageUrl(name)` (`src/lib/content/images.ts`), never a bare `/assets/...` path: a rebuilt picture gets a new URL, so browsers can cache each one forever and never show an old copy. Commit the generated file with the pictures.

`login-bg` is the picture behind sign-in, the dashboard and the party screen. It is applied by the global `.backdrop-art` class in `src/app.css`, which darkens it so text stays readable; the element also sets `style:--backdrop-image={BACKDROP_IMAGE}` (the hashed URL). Adding `use:parallax` (`src/lib/ui/parallax.ts`) to the same element makes the picture drift away from the cursor; it is skipped for people who ask for reduced motion. To change the picture, replace `art/images/login-bg.png` and run `pnpm asset:images`. To put it behind another screen, add the class, `style:--backdrop-image={BACKDROP_IMAGE}` and `use:parallax` to that screen's outer element. The expedition results screen uses it too.

Each pane on the Afflictions page has a picture, named by `AfflictionDef.image` in `src/lib/content/afflictions.ts`: `affliction-gloaming-banner` for the Gloaming, and `affliction-unknown-banner` for the panes of Afflictions nobody has met. A pane is 400px wide; the picture is fitted to that width and aligned to the top, the name sits over its first 250px, and below that it fades out behind the text. So make it portrait, at least 800px wide (for sharp screens), with the subject in the top part. Until a picture exists the pane shows a plain dark fade.

### Logo and site icon

Two pictures carry the game's name and mark. Both are cropped tight to the art, with the black they were drawn on made transparent so they sit on any backdrop:

- `logo` (the word UNDERCROFT, its O a way up a ladder) sits over the form on every signed-out page (`src/lib/ui/AuthPage.svelte`).
- `icon` (the O on its own) is the mark at the far left of the dashboard bar, a link home (`src/routes/(hub)/+layout.svelte`).

### Site icon

`icon` is also the site icon. `pnpm asset:images` makes two files from it at the site root, linked from `src/app.html`. They aren't hashed, because browsers and iOS ask for them by name:

- `static/favicon.ico`: the browser tab icon, PNG images at 16, 32, 48 and 64 px, transparent around the O.
- `static/apple-touch-icon.png`: 180 px, the O on black, for Add to Home Screen on an iPhone or iPad. iOS doesn't allow transparency there and rounds the corners itself, so the O keeps a margin. `apple-mobile-web-app-title` names the shortcut.

To change either picture, replace `art/images/icon` or `art/images/logo` (cropped, transparent around the art) and run `pnpm asset:images`. Commit `static/favicon.ico` and `static/apple-touch-icon.png` with the pictures.
